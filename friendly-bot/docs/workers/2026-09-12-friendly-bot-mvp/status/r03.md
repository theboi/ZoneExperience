## Delivered boundary

- OpenRouter requests accept only whitelisted/reserved keys, request ZDR and denied collection, and use prompt-safe DTOs. They do not opt into `logprobs`, debug, trace, or metadata logging fields. `logprobs` is not an OpenRouter prompt-logging control.
- `OpenRouterGateway` fails closed by default. It requires the exact non-secret environment value `FRIENDLY_BOT_OPENROUTER_INPUT_OUTPUT_LOGGING_ATTESTATION=disabled-globally-or-friendly-bot-key-excluded`; this is only an operator attestation, not evidence of the OpenRouter account state.
- The client contract returns only decoded operation values or typed static failures. Non-2xx provider bodies are status-only and unread; successful bodies have a 65,536-byte limit plus one oversize-detection byte. Gateway errors are raised after the lifecycle returns, never by a scope holding a raw response object.
- Routing selects distinct configured keys only; persona cursor advancement occurs only after a valid nonempty summary. Normal matching remains exact server attendance. Safety matching calls only F01's safety query, which admits exact leader/staff attendance or always-available responders, with no normal fallback. Reservations/rematches remain F01-UoW guarded and durable.
